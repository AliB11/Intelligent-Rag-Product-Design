# استقرار روی Vercel

برنامه یک پروژه Next.js است و مسیرهای API آن به‌صورت Vercel Functions اجرا می‌شوند؛ نیازی به سرور جداگانه یا تنظیم آدرس API در مرورگر نیست.

1. مخزن `AliB11/Intelligent-Rag-Product-Design` را در Vercel با گزینه **Add New → Project → Import Git Repository** وارد کنید. Root Directory را ریشه مخزن و Framework Preset را Next.js بگذارید. دستورات پیش‌فرض `npm install` و `npm run build` کافی هستند. Node.js نسخه 22 یا بالاتر لازم است (`.nvmrc` نسخه 22 را مشخص می‌کند).
2. برای ذخیره دائمی تاریخچه، یک PostgreSQL قابل دسترس از Vercel تهیه کنید و `DATABASE_URL` را در تنظیمات Environment Variables پروژه برای محیط‌های موردنظر (Production و در صورت نیاز Preview) قرار دهید. از آدرس اتصال و تنظیمات TLS توصیه‌شده توسط ارائه‌دهنده، ترجیحاً یک endpoint دارای connection pooling، استفاده کنید. هیچ رمز یا URL واقعی را در مخزن قرار ندهید. متغیرهای `POSTGRES_*` و `APP_PORT` فقط برای Docker Compose هستند.
3. پیش از استفاده از پایگاه داده، با نسخه بازبینی‌شده schema و با رعایت پشتیبان‌گیری، `npm run db:push` را از محیطی امن و متصل به همان پایگاه اجرا کنید؛ این دستور می‌تواند schema موجود را تغییر دهد. بهتر است Preview و Production پایگاه داده جدا داشته باشند. استقرار به‌طور خودکار schema را تغییر نمی‌دهد.
4. Deploy کنید. پس از آماده شدن، صفحه اصلی و `/api/health` را بررسی کنید. مقدار `persistence: available` اتصال و آماده‌سازی corpus را نشان می‌دهد؛ `unavailable` یعنی برنامه با corpus محلی کار می‌کند اما تاریخچه ذخیره نمی‌شود. یک درخواست تولید و سپس تاریخچه اجراها را نیز آزمایش کنید.

بدون `DATABASE_URL` برنامه همچنان قابل اجراست ولی داده‌ها و تاریخچه بین درخواست‌ها یا instanceهای سرورلس پایدار نیستند. اگر پایگاه پیکربندی شده اما در دسترس نباشد، برنامه به corpus محلی بازمی‌گردد و ذخیره‌سازی ممکن نیست؛ وضعیت health را بررسی کنید. هر instance اتصال‌های مستقلی دارد؛ pool کوچک به‌تنهایی سقف کل اتصال‌ها را تضمین نمی‌کند.

مسیر تولید خروجی streaming دارد و `maxDuration = 300` ثانیه درخواست می‌کند؛ زمان مجاز واقعی به پلن و تنظیمات Vercel بستگی دارد. اجراهای سنگین Monte Carlo ممکن است به محدودیت زمان، حافظه یا هزینه برخورد کنند؛ اندازه‌های واقعی موردنیاز را روی deployment آزمایش کنید. هیچ صف یا worker پس‌زمینه‌ای در این پروژه وجود ندارد و با قطع اتصال یا اتمام زمان تابع، تکمیل کار تضمین نمی‌شود.

**امنیت:** برنامه فعلاً احراز هویت یا محدودسازی نرخ درخواست ندارد. انتشار عمومی می‌تواند API محاسباتی و تاریخچه را در معرض دسترسی دیگران قرار دهد؛ پیش از استفاده از داده حساس، حفاظت دسترسی و محدودسازی مناسب اضافه کنید. برای کنترل اجرای نمونه، ابتدا از deployment پیش‌نمایش استفاده کنید.
